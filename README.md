# IdeaTree · 研究灵感时间轴

一个运行在本机的中文研究灵感工作台。横向是日期，纵向是 idea 分支，保留提出、调研、讨论、暂停、中止、完成和重启的过程。

将一个想法从提出、调研、讨论到继续推进、中止或衍生的过程，整理成一张可交互的时间地图。

## 开始使用

### Windows

1. 安装 [Node.js](https://nodejs.org/) 的 LTS 版本，本程序最低要求 Node.js 20。
2. 在 [Releases](https://github.com/Xiao-air/ideatree/releases/latest) 下载 `IdeaTree-1.1.0-windows.zip`，完整解压到你希望长期保存的位置。
3. 双击 **启动IdeaTree.cmd**，IdeaTree 会在独立应用窗口中打开，没有地址栏和标签页。
4. 可选：双击 **创建桌面快捷方式.cmd**。之后双击桌面 **IdeaTree** 图标即可打开；移动文件夹后重新创建快捷方式。

首次安装 Node.js 后，如启动器仍提示找不到 Node.js，请重新打开文件夹或终端后再试。下载包不附带 Node.js；应用本身没有需要安装的 npm 依赖。

Windows 启动器优先使用 Microsoft Edge 的应用窗口模式，未安装 Edge 时使用 Google Chrome；需要安装其中一个。窗口配置单独保存在 `data/window-profile/`，与日常浏览器配置分开。桌面快捷方式也使用这一启动方式，不会打开默认浏览器的普通标签页。此方式使用已有浏览器内核，并非内置运行时的原生客户端。

所有图标、字体回退及 D3 / Lucide 资源均可在本机使用。安装好 Node.js 后，日常运行不需要联网。应用窗口关闭不会停止本地服务；重复运行启动器会连接已有服务。需要网页方式时，仍可手动访问 <http://127.0.0.1:4317>。

### 从源码运行 / macOS / Linux

安装 Node.js 后，在项目目录执行：

```sh
npm start
```

然后打开 <http://127.0.0.1:4317>。使用终端启动时，可按 `Ctrl+C` 停止服务。Windows 快捷方式脚本仅适用于 Windows。

## 功能

- 日期主轴向右延续；idea 可从主轴或父 idea 的事件继续分支。
- 记录文献调研、导师讨论、实验、计算与状态决策，保留发展历史。
- 同一家族保持在主轴同侧，按时间跨度复用空闲行，减少交叉和纵向空白。
- 推进中的 idea 优先显示，已中止的 idea 归入左侧底部“已归档”。
- `Ctrl + 滚轮` 缩放整个页面；`Shift + 滚轮` 只缩放时间轴。
- 数据本地保存，支持 JSON 导入、导出及自动备份。

## 记录方式

- 首次打开的是明确标注的示例空间。点击 **开始我的记录**，确认后建立空白空间。
- **新建 idea**：填写简称、核心问题、首次提出时间与初始状态。
- **记录事件**：记录文献调研、导师讨论、计算或实验及决策。状态变化必须保留原因。
- **衍生 idea**：从当前 idea 或一条具体事件创建子分支。子分支与父分支的状态独立。
- **已拆分**：原方向不再独立推进，后续由已有子方向承接。先创建子分支，再通过状态决策明确选择“已拆分”；衍生本身不会自动修改父项目状态。父方向以实线停留在决策日期，列入左侧“已拆分”，不归入“已归档”。如重新开展独立工作，可记录为“推进中”。
- **自动归档母方向**：拆分方向的所有子分支及后续分支都中止后，母方向自动中止并归档，保留自动决策记录。仍有推进中、待评估、暂停或已完成的承接方向时，不自动归档；承接方向重新发展时，由系统自动归档的母方向会恢复为“已拆分”。手动设置的中止决定不自动改写。
- 点击当前状态可以记录新的决定。重启已中止的 idea 时，选择“推进中”；过去的中止记录会保留。
- 左侧可以展开或折叠子分支。拖动画布平移，使用加减按钮缩放；**今天**定位到今天，**适应全部**还原完整范围。
- 右侧详情展示完整事件。图上的标签会在拥挤时省略，完整内容仍可通过点击查看。
- 只记录已发生的事件，日期不能晚于今天。已衍生子分支的来源事件不能单独改变日期或删除。

## Radar备选库

默认主页仍是生长时间轴。左侧工作页面导航新增 **Radar备选库**，也可直接访问 <http://127.0.0.1:4317/radar.html>。

- 按“方向 → 问题家族 → 具体命题与来源版本”浏览，支持搜索、已有阶段、科学问题类型、声学作用方式和关键词筛选。
- 详情包含通俗概述、科学问题、既有阅读范围与证据缺口，以及分别记录的原始推荐、后续评审、用户决定、讨论材料和实际讨论状态。
- 历史引述条目正常分类展示并注明原件缺失；收录冲突项放在“待核对”，不计入保留命题。
- “导入Radar”只接受Radar JSON，先显示内容预览。更新时备份原Radar版本，重复导入相同内容不会增加副本；主时间树JSON备份仍从时间轴页面导入。
- Radar单独保存到 `data/radar-reserve.json`，备份位于 `data/radar-backups/`。时间树的 `data/ideatree.json` 不参与Radar导入。
- 来源链接仅只读打开导入清单引用的项目内文本。默认目录为 `data/radar-sources/`；可在本机 `data/radar-source-root.txt` 中填写来源目录的绝对路径，或通过环境变量 `IDEATREE_RADAR_SOURCE_ROOT` 指定（优先级最高），修改后重启服务。阅读记录和分类不代表新增科学验证或 Gate 通过。

## 周实验安排

在“周实验安排”工作页中，按周一至周日查看全天时间表。默认定位到上午，可上下滚动查看其他时段，并通过“前一周 / 后一周 / 本周”或日期选择跳转。

- 在空白网格拖拽框选时段，按 15 分钟刻度创建安排。跨多天框选时，会在每天的同一时段分别创建卡片；按 Esc 可取消框选。
- 也可点击“新建安排”直接填写日期、起止时间、实验名称和内容，起止时间支持 5 分钟精度。键盘聚焦星期列后按 Enter 也可创建。
- 点击卡片查看、修改内容、调整日期时间或删除；同一时段的安排自动并排显示。
- **先记工作，后排时间**：在周历上方的“本周工作清单”点击“记录工作”，只填写名称、内容及所属周，时间可以留待预约或协调后确定。待安排清单随周切换，可折叠以腾出周历空间。
- 点击清单项的“安排时间”，会带入原名称、内容和颜色；保存后，该项从待安排清单转为周历卡片，不重复生成工作。待安排项可编辑、删除或调整所属周，与日程一起导出、导入和自动备份。
- 日程允许提前安排未来实验，独立保存到 `data/weekly-schedule.json`。首次使用为空，不包含示例实验。
- 使用本页的“导出安排 / 导入安排”备份或恢复日程；自动备份在 `data/schedule-backups/`，保留最近 30 个版本。时间轴备份与实验安排备份独立。

## 数据和备份

实际记录保存到 **data/ideatree.json**，与浏览器缓存无关。每次保存会先将旧版本写入 **data/backups/**，保留最近 30 个版本。程序只监听本机地址，不会将研究记录上传到云端。

公开仓库和下载包只包含应用与通用示例，Radar 测试样本完全虚构，不包含作者的个人 idea、研究储备、课表或实验日程。你的 `data/`、备份、日志和 `.env` 文件已被 Git 忽略。迁移或更新应用前请先导出备份，并保留原来的 `data/` 文件夹；不要把个人导出文件加入仓库。

**导出备份**下载当前空间的 JSON。**导入备份**会先校验内容，再确认替换当前空间。可导入 `data/backups/` 中的历史文件以恢复记录。请定期导出重要记录；自动备份不能代替异地备份。

多个窗口同时编辑时，后保存的旧版本会被拒绝，避免覆盖其他窗口的修改。遇到保存失败，请保持页面打开、导出当前备份，再刷新。数据文件损坏时，服务会停止启动，不会静默重建并覆盖。

## 项目结构

```text
public/            界面、时间轴、共享数据校验
public/assets/     应用图标与 Windows ICO
public/vendor/     本地 D3 7.9.0、Lucide 0.468.0 及许可证
server.mjs         本地 HTTP 服务与 JSON 持久化
radar-api.mjs      独立 Radar 数据与来源读取
schedule-api.mjs   周实验安排和待安排工作的保存
start.ps1          Windows 本地启动器
create-shortcut.ps1 根据当前目录创建桌面快捷方式
tests/             数据与保存逻辑测试
data/              首次启动时创建的个人记录（不提交版本管理）
```

执行 `npm test` 运行测试。测试使用独立临时目录，不修改实际记录。

应用面向个人本地使用，不包含云同步、账号或多人协作。主时间轴记录已经发生的研究事件，周实验安排用于提前规划未来实验。

## 第三方资源

D3 与 Lucide 随项目本地分发，对应许可证保留在 `public/vendor/`。界面使用系统字体，无远程字体请求。
